# Cartalyst V1.1 Scope

## Intent

V1.1 focuses on practical multi-list and multi-inventory workflows with safe, local-first editing.

## In Scope

- Multiple shopping lists
- Multiple inventories
- Pantry as a user-created inventory name (not a fixed app section)
- Optional shopping list to inventory linking
- Simplified Home focused on:
  - create list
  - recently modified lists
- Bottom navigation structure:
  - Home
  - Lists
  - Inventories
  - Compare
  - Settings
- Price comparison with up to 5 options
- Safer editing UX with:
  - draft behavior for list edits
  - undo support for key list-edit actions

## V1.1 Phases

1. Organized Lists and Inventories
  - Introduce multiple lists and multiple inventories
  - Remove fixed pantry section behavior and treat pantry as user naming
2. Navigation and Focus
  - Keep Home list-focused
  - Move core destinations to Home, Lists, Inventories, Compare, Settings
3. Safe Editing and Review
  - Add gesture-driven list review interactions
  - Ensure key actions are reversible through undo
  - Protect full-list edits with draft apply/discard flow
4. Compare Expansion
  - Support 2-5 options with normalized ranking and clear winner summary

## Data Model Impact

- `shopping_lists` is no longer treated as a single active list workflow
- `inventories` is no longer constrained to a fixed pantry concept
- `shopping_lists.inventory_id` is nullable for optional linking
- Draft persistence is required for full-list editing safety
- Price compare result model expands from pairwise output to ranked multi-option output

## UX Principles

- Prioritize fast list creation and review over dense dashboards
- Keep action feedback immediate and reversible when destructive or status-changing
- Keep editing safe: users can stage full-list changes before apply
- Keep comparison output understandable at a glance: winner, short reason, clear table
- Keep controls visible on mobile: scroll-safe layouts and action accessibility above nav bars

## Out Of Scope

- AI features or AI predictions
- Receipt OCR
- Geofencing
- Backend sync
- Authentication

## Domain Language

- Inventory is the primary concept.
- Pantry is not a fixed system concept.
- A pantry is an inventory name chosen by the user.

## V1.1 Quality Expectations

- Keep local-first reliability
- Preserve clear architecture boundaries
- Provide polished empty and error states
- Keep behavior deterministic and testable
